# M33.8 — UI

## Context

`ui/src/app/features/forms/` (`form-builder.service.ts`, `sf-content-form.component.*`, `editor-outlet.component.ts`,
editors), `features/pages/page-editor.component.ts`, `page-issues-panel.component.ts`, `page-issues.util.ts`,
record and global set editors, `features/release/release-plan.component.ts`, `release-dialog.component.ts`, build
run/findings views, template/dataset/global-set CDL editors. Epic decision 12; user decisions 3, 7, 8, 9, 16–19.

## Goals

- `RuleEvaluationService`: calls `rules/evaluate` debounced (~400 ms) on change and on load, with a sequence number to
  drop stale answers; one instance per form (page content, each section, record, global set).
- Fills: `mode empty` applied to fields the user has not touched in this session that are empty or still hold the last
  live-fill value; `mode always` fields read-only with a "computed" badge; applying a fill does not mark the form
  dirty by itself beyond the normal autosave.
- Field states: required marker and read-only from `fieldStates` (per locale in the localized editor).
- Findings inline at their exact path (list rows, group members, bodies/sections), styled per level: hint (muted,
  editor only), info, warning, error; message already in the UI language.
- Save/autosave rejected with rule errors: keep local state, show errors inline, status "Not saved — fix N errors",
  retry autosave after the next change.
- Issues panel: grouped by level, scope filter, infos listed but not counted in the badge; hints not shown.
- Release plan/dialog: errors block with "Open" links; warnings require the "Release with warnings" checkbox
  (`acceptWarnings`); infos collapsed; planned fills listed.
- Build run view: `SF-GEN-0121` and rule warnings/infos with rule name and "Fix in …"; `RULE_REFERENCE` reason label.
- CDL editors: highlighting and completion for `rules {}` keywords, levels, scopes, functions and editor paths;
  diagnostics from `/cdl/validate`.
- Client validators reduced to instant format feedback; remove duplicates the server now reports.

## Acceptance criteria

- [ ] Vitest specs: debounce + stale-drop, fill application rules (touched/untouched, `always` read-only), states,
      inline placement per path, level styling, rejected-autosave state, release warning confirmation, issues panel
      grouping.
- [ ] Manual check in the running app: slug follows title until edited; `requiredWhen` toggles; a save-scope error
      blocks autosave; a release with warnings needs confirmation; a `fail` rule fails a build.
- [ ] `npx ng build` and `npx vitest run` green.

## Out of scope

- Backend (M33.1–M33.7).
