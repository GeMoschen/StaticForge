# M32.8 — UI

## Context

`project-settings-url-registry.component.*`, `url-registry.service.ts`, page / media / folder editors, import dialog
(M10/M11/M27.5). Epic decisions 9, 11; user decisions 15, 16.

## Goals

- Settings panel "Navigation URLs" → **"URLs"**: columns target (type icon, label, path), channel, locale, variant /
  page number, area, URL, overridden; filters type, locale, channel, area and a search field (asset name or URL);
  override and reset per row as today, plus "Reset all URLs of this asset".
- A **"URLs"** section in the page, media and folder editors: the asset's rows per channel / locale / variant / page,
  with override and reset (roles as in the API). Derived targets (indexed folders) show "Uses the URL of <index page>"
  with a link.
- Import dialog: option "Existing URLs" with the three modes (`ARCHIVE_WINS` default, `TARGET_WINS`, `REPLACE_ALL`),
  with a short hint each; analysis shows the URL conflicts.
- `SF-DOM-0200` / `SF-DOM-0201` shown as field errors on the override input.

## Acceptance criteria

- [x] Vitest specs for the panel filters, the editor sections and the import option.
- [x] Manual check in the running app: override a page URL from the page editor, build, follow the link.
- [x] `npx ng build` and `npx vitest run` green.

## Out of scope

- Backend (M32.1–M32.7).
