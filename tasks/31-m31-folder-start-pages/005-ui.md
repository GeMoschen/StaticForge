# M31.5 — UI: start pages in the Pages and Navigation screens

## Context

`sf-folder-detail`, `pages-list` (`pagesByFolder()`), page tree and its context menu, `navigation.component.ts:103`
(root not selectable — bug), `redirect-option.util.ts nearestIndexPage`, Channels settings ("Index page UID"),
`ProjectAccessStore.readOnly`, generated `schema.d.ts` (`FolderView.startPageUuid`, `PATCH /folders/{uuid}`). Epic
decision 12.

## Goals

- Folder detail: "Start page" select of the folder's own pages (plus "None"), hint "Renders as this folder's
  index.html"; saves via `PATCH` with `If-Match`; shows `SF-DOM-0111` with the conflicting page and a rename hint;
  read-only for viewers and archived projects.
- Root reachable: "All pages" (and the root's context menu "Folder settings…") opens the folder detail for
  `pages_root` with protected handling (no rename, UID or delete).
- Page tree: "Start page" badge on the chosen page; page context menu "Make start page of <folder>".
- Navigation: root selectable so its existing "Entry page" works; labels "Entry page" (navigation) vs "Start page"
  (index file) stay distinct.
- `nearestIndexPage`: folders' start pages first, then the `indexUid` rule; drop the "page named like the folder"
  heuristic.
- Channels "Index page UID" hint: "…unless the folder has a start page".

## Acceptance criteria

- [x] Vitest specs with `schema.d.ts`-typed fixtures (lessons: "Spec fixtures must have the API's real shape") for the
      select, the badge, the menu action, the root entry, `nearestIndexPage`, the conflict message, read-only state.
- [x] `npx ng build` and `npx vitest run` green.
- [ ] Manual check in the running app (own ports, scratch DB): set "Homepage" as start page of the root, build, output
      has `index.html`.

## Out of scope

- Backend (M31.1–M31.4).

## Notes / hazards

- The UI is zoneless: in Playwright checks wait for app-rendered state, not native control state.
- Manual check (2026-09-28, lane `m31-ui` on 34b4740 = M31.1 API only, backend 8096 + ng serve 4316, scratch DB/output/
  media/search roots): real API shapes confirmed (`FolderView.path` `/pages_root/`, `startPageUuid` explicitly `null`,
  page `folderPath` `/pages_root/`); "All pages" opens the root panel (no rename/UID/delete); with the channel's index
  file `home.html` choosing "Homepage" is refused and the panel names “Home” (UID “home”) with the rename hint
  (`SF-DOM-0111`); after renaming that UID, "Homepage" is saved (`GET /folders` shows it), the tree badges it and the
  other pages' menus offer "Make start page of All pages"; "All navigation" opens the root's "Entry page" drawer.
  Still open: "build, output has `index.html`" needs M31.2's output paths, which this lane's base doesn't contain —
  rerun the check after the lanes are merged.
- Deviation: `index` is a reserved UID (`SF-DOM-0102`), so the `SF-DOM-0111` conflict only arises with a channel whose
  index file stem is a non-reserved UID (e.g. `home.html`); the UI handles it for any stem.
- Deviation: new pages/folders created while "All pages" is selected still go to the project root with no
  `folderUuid` (unchanged request), not with the `pages_root` uuid.
